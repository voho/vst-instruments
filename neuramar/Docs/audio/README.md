# Neuramar demonstration audio

Eight rendered examples of what Neuramar does: a sound is learned, and its
memory is then played as an instrument. Every file is rendered by
[`Tools/RenderDemos.cpp`](../../Tools/RenderDemos.cpp) from the shipping
JUCE-free signal path — the same `SampleLearner` and `NeuramarEngine` the VST3,
Audio Unit and Standalone run — so a demonstration cannot drift away from what
the plug-in actually does.

Neuramar ships no samples, and neither does this directory. The training input
the model learns from is itself synthesized procedurally inside the renderer: a
plucked-then-sustained stiff-string tone at A3, assembled from the same
ingredients the regression suite's learning fixtures use. It carries a dense
stretched partial series `f(n) = n f0 sqrt(1 + B n^2)` with `B = 3·10⁻⁴` for
the harmonic Core and the stiff-string fit, a slowly darkening spectrum and a
gently breathing partial balance for the neural trajectory, a noisy pluck and a
low breath floor for the Air layer, and two sustained inharmonic body
resonances for the Bone modes. The renderer fits the model from that tone
exactly as the plug-in fits a dropped file — root inference, harmonic, Air and
Bone analysis, deterministic Adam training — and then plays the result. The
whole chain, input included, is code.

## How to listen to them

The set is ordered so it can be played straight through:

- **01** is the training input itself, untouched by the engine: the entire
  "recording" everything below was learned from, heard twice.
- **02** is the claim at the heart of the instrument: the training tone once,
  then the fitted model replaying its learned root note. The model is not
  playing back the tone — it is rendering its compact memory of it.
- **03–04** are generalisation: a phrase across two octaves in which every
  pitch but the root is extrapolated from one note of evidence, then the same
  five velocities with **Touch** at zero (velocity is level alone) and fully
  open (harder notes lean brighter and breathier).
- **05–06** take the learned anatomy apart. 05 holds one note while the
  harmonic Core, the noisy Air and the inharmonic Bone modes are brought in
  and out; 06 moves the learned resonant body up and down two formant shifts
  in each direction while the played pitch stays put.
- **07** is the engine as a polyphonic instrument: a five-voice pad assembled
  note by note with **Awaken** fades, **Horizon** width — listen in headphones;
  the Air layer's second realization is decorrelated — and **Orbit** keeping
  the held chord breathing inside its learned loop.
- **08** is the fitted stiff-string coefficient heard directly: the same note
  with **Stretch** forcing an ideal harmonic series, rendering the learned
  stretch, and exaggerating it to twice the fitted value.

## Levels

Each take is rendered with generous headroom and then normalised to −3 dBFS, so
the files can be auditioned one after another without reaching for the volume.
The renderer refuses to write a take that reached full scale before
normalisation, because such a file would document the 16-bit clamp rather than
the model.

The **rendered peak** column below is the level each take produced before that
normalisation, relative to the engine's output stage at the reduced gain the
renderer uses. It is the honest measure of how loud each take actually is: the
five-voice pad is genuinely louder than a single faithful replay.

## Regenerating them

```bash
cd neuramar
cmake -S . -B build-dsp -DCMAKE_BUILD_TYPE=Release \
  -DNEURAMAR_BUILD_PLUGIN=OFF -DBUILD_TESTING=OFF
cmake --build build-dsp --parallel --target NeuramarRenderDemos
./build-dsp/NeuramarRenderDemos Docs/audio
```

The render is deterministic end to end: the training tone is a closed-form
function of the sample index, the learner is deterministic by construction —
the regression suite proves equal input produces byte-identical models — and
the engine's noise streams are seeded per note. Running the tool on an
unchanged model rewrites the same bytes and commits nothing. The table above is
regenerated in place by the same command, so the documented levels cannot drift
away from the committed files either.

A take that is renamed or removed from the renderer's table is deleted from
this directory on the next full render, so a stale WAV cannot survive here
after the demo that produced it has gone.
